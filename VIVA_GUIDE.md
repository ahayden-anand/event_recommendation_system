# Campus Event Recommendation System - Viva & Project Defense Guide

## 1. Project Overview & Architecture
The **Java-Based Campus Event Recommendation System** is a desktop application developed with **Java Swing** for GUI, **JDBC** for relational database connectivity with **MySQL**, and a pure Java **100-point rule-based recommendation engine**.

### Architectural Pattern: Layered MVC (Model-View-Controller / DAO)
- **Model Layer:** `Student.java`, `Event.java`, `Registration.java`, `EventRecommendation.java`
- **View Layer:** `Main.java`, `StudentDashboard.java`, `EventManagerDashboard.java`
- **Controller & Algorithm Layer:** `RecommendationEngine.java`, `EventManager.java`
- **Data Access Layer (DAO):** `DBConnection.java`, `EventDAO.java`, `RegistrationDAO.java`, `StudentDAO.java`

## 2. Recommendation Algorithm Steps
1. **Hard Filtering:**
   - **Budget Filter:** If `event.fee > student.maxBudget`, exclude immediately.
   - **Department Filter:** If event is not `'All'` and does not contain student's department, exclude.
   - **Academic Year Filter:** If event eligible year is not `0` (all years) and does not equal student year, exclude.
2. **Scoring Formula (Max 100 Points):**
   - **Academic Eligibility:** `+10 points`
   - **Budget Affordability:** `+20 points` (free events or within student's budget)
   - **Interest Match:** `+30 points` (student interests contain event category)
   - **Skill Match:** `+25 points` (student possesses required skills)
   - **Time Slot Match:** `+15 points` (availability matches event schedule)
3. **Sorting:**
   - Suitable events are ordered in descending order of suitability score using **Bubble Sort** (`O(n^2)` time complexity, `O(1)` auxiliary space).
4. **Explanations:**
   - Every matched criterion appends an explanation to the match reason string (e.g. `Interest matched: Coding [+30]`).

## 3. High-Yield Viva Questions & Answers

### Q1: Why did you use `PreparedStatement` instead of `Statement` for database queries?
**Answer:** `PreparedStatement` pre-compiles the SQL query structure on the database server. It uses parameterized placeholders (`?`) where values are bound using methods like `setString()` and `setInt()`. This provides two major advantages:
1. **Security:** It prevents SQL Injection attacks because input values are never concatenated as executable SQL syntax.
2. **Performance:** Pre-compiled statements can be reused efficiently by the database engine.

### Q2: What is the difference between AWT and Swing?
**Answer:**
- **AWT (Abstract Window Toolkit):** Heavyweight components that rely on the native operating system peers. Look-and-feel is platform-dependent.
- **Swing:** Lightweight components written entirely in pure Java. They are drawn by Java code and provide a consistent, pluggable look-and-feel across all operating systems. Swing also follows a separable MVC architecture.

### Q3: Why is GUI code executed inside `SwingUtilities.invokeLater()`?
**Answer:** Swing components are not thread-safe. `SwingUtilities.invokeLater()` ensures that GUI creation and widget modifications execute on the **Event Dispatch Thread (EDT)**, preventing multi-threaded concurrency bugs and UI race conditions.

### Q4: How does the Delegation Event Model work in Java?
**Answer:** The Event Delegation Model consists of three parts:
1. **Event Source:** The GUI widget the user interacts with (e.g. `JButton`).
2. **Event Object:** Generated by the source upon user interaction (e.g. `ActionEvent`).
3. **Event Listener:** An interface (e.g. `ActionListener`) that receives the event object and executes handler code (`actionPerformed(ActionEvent e)`).

### Q5: What is Encapsulation, and how did you implement it?
**Answer:** Encapsulation is the OOP principle of bundling data and methods that operate on that data into a single unit, while restricting direct access to the internal state. In `Student.java` and `Event.java`, all attributes are declared `private`, and access is only permitted through public getter and setter methods.

### Q6: How do you handle invalid inputs in your forms?
**Answer:** We perform defensive checks:
- Text fields are verified using `.trim().isEmpty()`, and empty required fields prompt a `JOptionPane.showMessageDialog(..., WARNING_MESSAGE)`.
- Numeric fields like `fee` and `budget` are parsed using `Double.parseDouble()`, wrapped inside a `try-catch (NumberFormatException)` block to handle non-numeric text gracefully.

### Q7: What is the purpose of `DefaultTableModel` in `JTable`?
**Answer:** `DefaultTableModel` is the data model that backs a `JTable`. It stores the column headers and row data. By modifying the model (via `addRow()`, `setRowCount(0)`, or overriding `isCellEditable()`), the view (`JTable`) automatically updates without having to recreate table widgets.

### Q8: What happens when an event is deleted from the database?
**Answer:** In `database.sql`, the `registrations` table defines a foreign key constraint with `ON DELETE CASCADE`:
```sql
FOREIGN KEY (event_id) REFERENCES events(event_id) ON DELETE CASCADE
```
When an event is deleted, MySQL automatically removes all registrations tied to that event, preserving database referential integrity.

### Q9: How is role-based authentication implemented in your application?
**Answer:** In `Main.java`, when the user signs in with their username and password, `UserDAO.authenticate()` verifies the credentials against the `users` table. The returned `User` record holds the user's role (`STUDENT` or `COORDINATOR`). Based on this role, the application automatically routes the user:
- `STUDENT` -> opens `StudentDashboard` with student profile, recommendations, and registration tools.
- `COORDINATOR` -> opens `EventManagerDashboard` with event CRUD management and attendee tracking.
A student cannot access the coordinator portal simply by selecting a role in a dropdown.

### Q10: How does your application connect to MySQL automatically and handle database offline states?
**Answer:** In `DBConnection.java`, database credentials (`URL`, `USER`, `PASSWORD`) are encapsulated in one centralized location. When the application starts, `DBConnection.initializeDatabase()` tests the connection silently and auto-creates required tables without prompting the user. If MySQL is offline or credentials differ, the application safely detects this using `isConnectionAvailable()` and falls back to an in-memory standalone mode so the system never crashes.
